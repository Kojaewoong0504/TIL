# Boyer-Moore 문자열 검색 알고리즘 정리

Boyer–Moore 알고리즘은 문자열 검색 알고리즘 중에서도 **가장 빠르고 실용적인 알고리즘 중 하나**입니다. 이 글에서는 Boyer-Moore 알고리즘의 기본 개념, 핵심 규칙(Bad Character Rule, Good Suffix Rule), 그리고 실제 탐색 방식에 대해 정리합니다.

---

## ✅ 1. Boyer-Moore 알고리즘의 핵심 아이디어

> "비교는 오른쪽 끝부터 시작하며, 실패하면 패턴을 최대한 멀리 점프시킨다."

- 일반적인 문자열 검색은 왼쪽부터 비교하지만,
- Boyer–Moore는 **오른쪽부터 왼쪽으로 비교**합니다.
- 실패 시, **두 가지 규칙 중 더 먼 쪽으로 점프**하여 검색 속도를 높입니다.

---

## ✅ 2. 주요 전처리: 두 가지 점프 규칙

### 🔹 1. Bad Character Rule

- **틀린 문자를 기준**으로 패턴을 이동
- 현재 틀린 문자가 패턴 내 어디에 다시 등장하는지 확인
- 없으면 → 패턴 전체를 넘기기

#### 예시:
```
Text:   ... A B C D E ...
Pattern:     A B C D F
               ↑   ↑
               |   틀림 (E ≠ F)
```  
→ E는 패턴 내 없음 → 패턴 전체 점프

---

### 🔹 2. Good Suffix Rule

- **이미 맞은 접미사**를 기준으로 이동
- 해당 접미사가 패턴 내 어디서 다시 등장하는지 확인
- 등장하면 → 해당 위치로 정렬하여 점프
- 없다면 → 접미사의 일부 또는 전체 이동

#### 예시:
```
Pattern: A B C D A B C
Text:        A B C D A B E
                       ↑ 틀림
```  
→ 이미 맞은 접미사 `A B`가 앞쪽에도 존재 → 그 위치로 패턴 이동

---

## ✅ 3. 실제 탐색 시 동작 방식

1. 패턴을 텍스트에 정렬하고, **오른쪽에서부터 비교** 시작
2. 비교 실패 시:
   - Bad Character Rule과 Good Suffix Rule로 점프 거리 계산
   - **더 큰 거리로 점프**
3. 이동 후 다시 오른쪽부터 비교 반복

---

## ✅ 4. 전처리 테이블 만들기

### ▶ Bad Character Table
- 크기: 일반적으로 256 (ASCII)
- 각 문자에 대해 **가장 마지막 등장 인덱스** 저장

### ▶ Good Suffix Table
- 각 접미사에 대해:
  - 패턴 내에서 다시 사용할 수 있는 위치 계산
  - 없으면 → 더 짧은 접미사 탐색
  - 최종적으로 없으면 → 패턴 전체 이동

## ✅ 5. Boyer-Moore의 장점과 활용

| 장점 | 설명 |
|------|------|
| 매우 빠름 | 평균적으로 가장 빠른 문자열 검색 알고리즘 중 하나 |
| 멀리 점프 가능 | 비교 실패 시 최대한 멀리 이동 가능 |
| 실전 활용도 높음 | grep, IDE 검색, 컴파일러 등에서 사용 |

## ✅ 6. KMP와 비교

| 항목 | KMP | Boyer-Moore |
|------|-----|---------------|
| 비교 방향 | 왼쪽 → 오른쪽 | **오른쪽 → 왼쪽** |
| 점프 방식 | LPS 배열 기반 점프 | Bad Character + Good Suffix 기반 |
| 평균 속도 | 빠름 | **더 빠름** |
| 구현 난이도 | 쉬움 | **어려움** |

## ✅ 결론

Boyer–Moore는 매우 빠르며 실전에서도 널리 활용되는 문자열 검색 알고리즘입니다. 
두 가지 전처리 규칙만 잘 이해하면, 매우 효율적인 검색이 가능합니다.

강력한 검색 성능이 필요할 때 꼭 고려해볼 만한 알고리즘입니다.
